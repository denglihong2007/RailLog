# 更新日志的写法

*迁移自 Claude Code 项目记忆 · 更新于 2026-10-10*

RailLog 的更新日志（GitHub release body，同时是 App「更新日志」页显示的内容）是写给**普通用户**的，不是给开发者看的。固定三段：`### 🚀 **新特性 (Features)**`、`### 🎨 **交互与体验 (UI/UX)**、`### 🐛 **修复 (Fixes)**；条目形如 `- **小标题**：说明`，或直接一句说明，引号用「」。最终以 md 代码块交付，用户自己贴进 release。

不写的东西（2026-10-11 用户明确要求）：

- **成就并成一条**：`- **成就扩充**：新增「A」「B」「C」。` 只列名字，不写经验值、上限、取得条件、隐藏标志，也不按周分批（对齐 2.5.0 的写法）。
- **实现细节**：排序公式、API 参数名（如 `mode`）、写锁／超时／MailKit 默认值、内部字段名（如 `owner_user_id`）、纯重构的行数增减、内部自造叫法（如「登乘跳」「偏好集」）。要么换成用户看得懂的说法，要么删掉。
- **开发侧提醒**：例如「这条与规格表有意不一致，diff 会一直报差异」——这类内容属于提交说明和代码注释，不进发布说明。

**Why:** 发布说明面向全体用户，实现细节对他们没有意义；成就写细节会把日志变成规格表。

**How to apply:** 每个短语自问「普通用户读了有什么用」，答不上来就删或改成行为描述。版本范围与核对方式见 [release-notes-range-derivation](./release-notes-range-derivation.md)。
