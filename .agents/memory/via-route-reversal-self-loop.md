# 换向行程的折返怎么合并

*迁移自 Claude Code 项目记忆 · 更新于 2026-10-11*

2026-10-11 排查并修掉「26.6.18 T7 延安→镇安 为什么有一个 灞桥→灞桥」。

背景：换向（如 T7 在 西安 换向）就是车在同一条线上原路退回去。T7 从东边（新丰镇→窑村→灞桥）
进 西安，折返后再往东退到 灞桥 才上 西康线 南下，`灞桥↔西安` 那 10 km 走两遍。区间 1 的最后
一条边和区间 2 的第一条边正好是 `陇海线 灞桥→西安` / `陇海线 西安→灞桥`，逐条边合并时被并成一段。

**判据（关键）**：折返不一定退回本段的起点，所以「首尾同名」是漏的。反例：区间 1 走
`宁西线西合段 新丰镇→窑村→灞桥→西安 35 km`，区间 2 第一条边 `宁西线西合段 西安→灞桥 10 km`，
合并出来是首尾**不同**名的 `新丰镇→灞桥 45 km`，同样是自相重叠的走法。正确判据是
**本段已经走过的站又被走一遍**：按段维护已访问站集，flush 后重置为新段的起终两站，折返处一律断开，
记成 灞桥→西安 + 西安→灞桥（里程各算一遍，不是重复计数）。修之前展开站表和贴轨都只按
「线路名 + 首尾站」查，重叠那段被抹掉，换向站 西安 整站从行程站表里消失。回归用例在
`app/test/route_service_test.dart` 的「换向处断开，记成进退两段」两条（第二条就是内部折返那个反例，
旧判据下必挂）。实现见 `_mergeSections`（`_mergeEdges` 与日志 `_describeEdges` 共用）。

顺带记一个 **西康线** 数据毛病（未修）：`灞桥 10 / 田王 7` 与站序（灞桥 index 在 田王 之前）
自相矛盾（田灞联络线上是 灞桥 8 / 田王 0），于是 灞桥→镇安 按行序走成 3+12+… = 137 km，
比里程桩净差 131 多 6 km；时刻表给 西安→镇安 141 km，routes.db 最短却要 147 km。
