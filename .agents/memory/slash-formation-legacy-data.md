# 「/」编组分隔符与存量数据冲突

*迁移自 Claude Code 项目记忆 · 更新于 2026-10-02*

2026-10-02 起，Dart 与 C# 两侧的车型解析器把 `/` 定义为**编组分隔符**（`+` 分同编组车型、`&` 分同车型车号）。但改动前库里已有 55 条含 `/` 的有效行程，其中 28 条是「车号/车号」写法，并非编组变化——典型：`DF11G-0001/0002+YW25T`、`CR400BFG-5176/5179`、`HXD1D-0479/0033+YW25K`。

**Why:** 用户明确选择了「一律按编组分隔」，不做「/ 后跟纯数字就当归一化为 &」的智能兼容。所以这些旧串现在会被拆错（例如 `DF11G-0001/0002` 变成机车 `DF11G-0001` + 一个无效客车 `0002`），且是静默的：会影响统计排行、`entity_detail_page` 的车型实体匹配、`entity_reviews` 的 EntityKey（可能变孤儿），以及全部车型相关成就。

**How to apply:** 用户说另行清理。要做时先 `SELECT Id, RollingStock FROM TripRecords WHERE DeletedAt IS NULL AND RollingStock LIKE '%/%'`，把 `/` 后紧跟纯数字的改写为 `&` 即可。改动前的解析行为可参照本次提交的父亲版本。
